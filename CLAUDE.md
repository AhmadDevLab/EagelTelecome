## Project overview

Eagle Telecom is a lead-capture form app split into two independently-run projects that only talk to each other over HTTP:

- **`backend/`** — Laravel 13 (PHP 8.3+) JSON API. No Blade/Inertia UI is served from here despite the default Laravel scaffold files present (see "Unused scaffold" below).
- **`frontend/`** — a separate React 19 + Vite SPA (not a Laravel Vite build) that consumes the API. It has its own `package.json`, `vite.config.js`, and dev server, and is not wired into the backend's asset pipeline.

Public visitors submit a lead form (name, zip, phone) which auto-generates a fake email and a fake US IP/location; an admin panel (password + short-lived cache token) lists/searches submissions.

## Commands

### Backend (run from `backend/`)

```sh
composer install
php artisan migrate            # requires MySQL running, see backend/.env (DB_DATABASE=eagle_telecom_forms)
php artisan serve              # API at http://127.0.0.1:8000
php artisan test               # or: vendor/bin/phpunit
php artisan test --filter=testName
php artisan test path/to/Test.php
vendor/bin/pint --dirty --format agent   # format PHP files you touched, run before finishing any PHP change
```

### Frontend (run from `frontend/`)

```sh
npm install
npm run dev       # Vite dev server at http://localhost:5173
npm run build
npm run lint       # oxlint
```

Both dev servers must run simultaneously for the app to work end-to-end (frontend calls `VITE_API_BASE_URL`, default `http://127.0.0.1:8000/api`).

### Backend conventions (Laravel Boost)

`backend/AGENTS.md` contains the full set of Laravel/PHP/Pint/PHPUnit conventions generated by Laravel Boost (constructor promotion, explicit return types, `php artisan make:*` for new files, run Pint before finishing, etc.) — read it before making backend changes. `backend/CLAUDE.md` is a stale Boost bootstrap file (pre-install instructions); the real guidance lives in `AGENTS.md`.

## Architecture

### Data flow

1. `POST /api/submissions` (public, no auth) → `FormSubmissionController::store` validates input, then on `FormSubmission` (`backend/app/Models/FormSubmission.php`):
   - `generateFormId()` / `generateVerificationCode()` — unique human-readable IDs.
   - `generateFakeEmail($first, $last)` — `firstnamelastname` + 2–3 random digits `@` `config('eagle.fake_email_domain')` (default `gmail.com`, overridable via `FAKE_EMAIL_DOMAIN` env). Mirrored client-side in `frontend/src/lib/email.js` for the live preview shown before submit — keep both in sync if the format changes.
   - `generateFakeUsIp($zipCode)` — resolves the submitter's state from the **ZIP3 prefix** (first 3 digits of the zip) via the `ZIP3_STATE_RANGES` table (standard USPS zip-prefix-to-state ranges, matches what public zip lookups show), then generates a random non-private-range IPv4. The IP itself has no real geo tie to the state — only the `ip_location` label is derived from the zip; `randomPublicIp()` just avoids RFC1918/loopback/link-local ranges.
   - The submitter's *real* request IP is stored separately as `ip_address` (`$request->ip()`), distinct from the fake `fake_ip_address`/`ip_location` pair.
2. Admin auth is **not** Sanctum/sessions — `POST /api/admin/login` checks `config('eagle.admin_password')` (`ADMIN_PASSWORD` env) and stores a random token in `Cache` as `admin_token:{token}` with TTL `eagle.admin_token_ttl_minutes` (default 480). The `admin.auth` middleware (`App\Http\Middleware\AdminAuth`, aliased in `backend/bootstrap/app.php`) just checks `Cache::has()` on the bearer token — no user/model association.
3. `GET /api/admin/submissions` (behind `admin.auth`) does a simple multi-column `LIKE` search (`q` param) across form_id/verification_code/name/email/phone/zip, paginated.

### Config

`backend/config/eagle.php` is the single place for app-specific settings (`fake_email_domain`, `admin_password`, `admin_token_ttl_minutes`) — check here first, not scattered env() calls, when changing generation/auth behavior.

### Frontend structure

- `App.jsx` — two routes: `/` → `Landing` (EtelQuotes lander; lead form lives in `components/LeadForm.jsx`, styles in `landing.css`), `/admin` → `AdminPage` (login gate + submissions table), everything else redirects to `/`.
- `lib/api.js` — shared axios instance (`VITE_API_BASE_URL` env) and `authHeaders()` helper reading the admin token from `localStorage` (`eagle_admin_token`).
- `lib/email.js` — client-side mirror of the backend's fake-email format, used only for the live preview field.
- No component library/design system — plain CSS in `src/index.css` with BEM-ish utility classes (`.card`, `.badge`, `.mono`, table-specific classes like `.submissions`, `.form-id-cell`).

### CORS

`backend/config/cors.php` only allows the origin in `FRONTEND_URL` (env, default `http://localhost:5173`) — update this if the frontend dev port/host changes.

### Unused scaffold (don't build on these)

`backend/resources/{js,css,views}`, `backend/vite.config.js`, and `backend/package.json` are leftovers from Laravel's default starter kit (Tailwind + `resources/views/welcome.blade.php`) and are not part of the running app — the real UI is entirely in the top-level `frontend/` project. `backend/database/database.sqlite` is likewise unused; the app connects to MySQL per `backend/.env` (`DB_CONNECTION=mysql`, `DB_DATABASE=eagle_telecom_forms`).

### Tests

`backend/tests/{Unit,Feature}/ExampleTest.php` are the default Laravel placeholders — there is no real feature-test coverage yet for the submission/admin flows.
